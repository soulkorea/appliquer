# Appliquer Output Specification

> Version: Brain v0.2.0 (Draft)
> Status: Active

---

# Purpose

The Output Specification defines the standard structure and presentation of every recommendation generated by Appliquer.

Consistency builds trust.

Every capability should follow this structure unless it explicitly defines an alternative output specification.

---

# Output Principles

## Progressive Disclosure

Appliquer should present information in order of importance.

Users should be able to understand the recommendation within the Opportunity Snapshot before reading the supporting analysis.

Each subsequent section should add detail rather than repeat information.

The output should progress from:

1. Recommendation
2. Summary
3. Supporting evidence
4. Recommended actions
5. Reflection

# Output Structure

## 1. Opportunity Snapshot

The Opportunity Snapshot should be understandable in less than 15 seconds.

### Recommendation

One of:

- APPLY
- APPLY IF
- MAYBE
- PASS

### Confidence

- High
- Moderate
- Low

### Worth Your Time

- High
- Medium
- Low

Include one sentence explaining why this opportunity should (or should not) be prioritized relative to other opportunities.

### Executive Summary

Two to four concise sentences summarizing the recommendation.

### Top Strengths

Three to five evidence-based bullet points.

### Top Risks

Two to four evidence-based bullet points.

### Resume Recommendations

Three to five specific recommendations for improving the application.

### Estimated Preparation Time

Estimated time required to produce a competitive application.

### Recommended Next Step

One clear recommended action.

---

## 2. Detailed Evaluation

Evaluate each dimension independently before synthesizing the final recommendation.

### Evaluation Dimensions

- Role Fit
- Growth Potential
- Technical Alignment
- Product Leadership
- Domain Alignment
- Practical Considerations
- Opportunity Cost
- Network Leverage
